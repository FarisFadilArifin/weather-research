# Ordinal Probabilities Model 2

## Canonical station-baseline architecture

Every station baseline now uses one XGBoost point model, a conditional-Gaussian
benchmark, four XGBoost-dependent ordinal research candidates, and a canonical
three-member ordinal ensemble:

```text
native_ordinal_reference     # comparison-only
blended_ordinal              # voting
shared_slope_ordinal         # voting
pure_ordinal                 # voting
```

All three voting artifacts must be available, two station-specific confidence
votes are required, and selected-bucket probability is the median of the three.
The native reference remains non-voting so a near-duplicate of pure ordinal
cannot receive an extra vote. KDAL fits native Fahrenheit offsets and aggregates
to 2°F markets; RJTT, RKSI, and RKPK fit native Celsius offsets for 1°C markets.

The canonical implementation is
`src/calibration/station_probability_models.py`. All candidates train only from
honest chronological predictions made by the single XGBoost point model.

## Historical three-base-model lineage

The material below documents the earlier ordinal implementation. Its
XGBoost/LightGBM/CatBoost feature contract remains useful for interpreting
existing live artifacts, but it is not the new notebook-training contract.

### Model

- Target: `round(actual_high_f) - round(point_prediction_f)`.
- Classes: `≤-4`, `-3`, `-2`, `-1`, `0`, `+1`, `+2`, `+3`, `≥+4`.
- Learner: eight cumulative binary logistic regressions.
- Selection: forced `ordinal_logistic`.
- Empirical blend: disabled with learned-model weight `1.0`.
- Calibration: temperature scaling selected on the last 90 days of each
  training period.
- Output: offset probabilities expanded to integer-degree probabilities, then
  aggregated into the actual 2°F market buckets.

### Preprocessing

Each cumulative model owns a scikit-learn pipeline:

```text
median imputer -> standard scaler -> logistic regression
```

The imputer and scaler are fitted only on that fold's training rows. There is no
skew transform and no feature winsorization or clipping in the verified V27
implementation. Missing indicators are explicit inputs for optional live-safe
source features.

### Seoul and Tokyo Asia no-peak feature profile

Seoul/RKSI and Tokyo/RJTT use
`probability_feature_names(include_peak_features=False,
feature_profile="asia_no_peak")`.

It also contains 59 inputs, but the provider-specific contract is:

```text
gfs_high_f
gefs_high_f
jma_msm_high_f
gfs_minus_point_f
gefs_minus_point_f
jma_msm_minus_point_f
```

The remaining derived, observation, consensus, calendar, and missing-indicator
roles parallel the common no-peak profile. HRRR and NBM are intentionally absent.
The probability models use honest 2024–2025 point-stack rows, evaluate 2025
forward, and treat 2026 as an exploratory holdout.

Seoul and Tokyo no longer use this document's rounded-Fahrenheit target or 2°F
market aggregation. They keep the same 59-feature `asia_no_peak` serving
contract but fit Celsius offsets directly using classes
`<=-3, -2, -1, 0, +1, +2, >=+3`, expands open tails only across exact offsets
supported by pre-2026 training data, and exports whole-1°C probabilities. See
`NOTEBOOK_STANDARD.md` and each station's target contract artifact.
